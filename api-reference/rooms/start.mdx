---
title: "Start the Game and Assign Roles — POST /api/rooms/start"
sidebarTitle: "Start Game"
description: "Host starts the game: selects a random Narrator, assigns shuffled roles to all other players per room settings, and transitions room status to started."
---

The `/api/rooms/start` endpoint kicks off a game session. It may only be called by the room host while the room is in `waiting` status and at least 2 players are present. The server picks one player at random to become the **Narrator** (who oversees the game but does not receive a gameplay role). All remaining players — the *participants* — receive shuffled roles according to the room's settings: `mafiaCount` Mafia roles are assigned first, then Doctor and Detective (always included), then Silencer if `lady` is enabled, then any custom roles in definition order, and finally enough Villager roles to fill the remaining slots. The room status is then set to `started` and `roundState` is cleared.

## Request

<ParamField body="roomCode" type="string" required>
  The 6-digit numeric room code of the room to start.
</ParamField>

<ParamField body="clientId" type="string" required>
  The browser-generated UUID of the requesting player. Must belong to the room's current host.
</ParamField>

## Response

<ResponseField name="data" type="object">
  <Expandable title="data fields" defaultOpen>
    <ResponseField name="ok" type="boolean">
      Always `true` when the game has been started successfully.
    </ResponseField>
  </Expandable>
</ResponseField>

## Role Assignment Logic

<Info>
  Understanding how roles are assigned can help hosts configure `mafiaCount` and custom roles correctly for their player count.
</Info>

1. **Narrator selection** — one player is chosen uniformly at random from the full player list and marked `is_narrator = true` with the `Narrator` role. They are excluded from all gameplay role assignment.
2. **Role pool construction** — the remaining players (participants) receive roles in this priority order:
   - `mafiaCount` × `Mafia` — clamped: minimum `1`, maximum `participants.length - 1` (computed as `Math.min(Math.max(settings.mafiaCount, 1), participants.length - 1)`)
   - `Doctor` (always included)
   - `Detective` (always included)
   - `Silencer` if `lady` is `true`
   - Custom roles in the order defined, each repeated `count` times
   - `Villager` fills all remaining slots
3. **Shuffling** — the role pool is shuffled using a Fisher-Yates algorithm before being assigned positionally to participants.
4. **Room update** — the room's `status` is set to `"started"` and `roundState` is reset to `null`.

<Note>
  If the room has fewer participants than the total number of special roles, roles are assigned greedily in priority order until all participant slots are filled. Villager slots are only added after all special roles are exhausted or participant slots are used up.
</Note>

## Error Responses

<ResponseField name="400 — Missing roomCode or clientId" type="string">
  One or more required body fields are absent or empty.
</ResponseField>

<ResponseField name="400 — At least 2 players are required." type="string">
  The room has fewer than 2 players total, or there are no participants left after Narrator selection.
</ResponseField>

<ResponseField name="403 — Player not found" type="string">
  No player with the given `clientId` exists in this room.
</ResponseField>

<ResponseField name="403 — Only host can start the game" type="string">
  The calling player exists but does not hold the host flag.
</ResponseField>

<ResponseField name="404 — Room not found" type="string">
  No room matches the provided `roomCode`.
</ResponseField>

<ResponseField name="405 — Method not allowed" type="string">
  Request was not `POST`.
</ResponseField>

<ResponseField name="409 — Room already started" type="string">
  The room's status is no longer `waiting`.
</ResponseField>

<ResponseField name="500 — Database error" type="string">
  One of: `Failed to assign roles`, `Failed to assign narrator`, or `Failed to update room status` — indicates a Supabase database error during role assignment or room status update.
</ResponseField>

## Example

```javascript
const response = await fetch('/api/rooms/start', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    roomCode: '123456',
    clientId: 'a1b2c3d4-e5f6-7890-abcd-ef1234567890'
  })
});
const { data } = await response.json();
// data.ok === true — game has started, roles assigned
console.log(data.ok);
```

<Warning>
  Once the game is started, the room status becomes `started` and new players can no longer join. Any subsequent `/api/rooms/join` calls from unknown `clientId`s will receive a `409` error.
</Warning>

<Tip>
  After a successful start, every client's polling loop via `/api/rooms/state` will observe `status: "started"` and a populated `role` field for the requesting player on the next tick (within ~2 seconds).
</Tip>
