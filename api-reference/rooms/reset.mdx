---
title: "Reset the Game to Lobby State — POST /api/rooms/reset"
sidebarTitle: "Reset Game"
description: "Resets a room back to the waiting lobby. Clears all player roles, confirmed flags, narrator flags, and round state. Only the host may call this endpoint."
---

The `/api/rooms/reset` endpoint returns a room to the `waiting` state after a game has concluded or when the host wants to start fresh with new role assignments. It strips every player's `role`, `has_confirmed`, and `is_narrator` flags back to their defaults, and clears `roundState` from the room's settings. The room's existing player list, host assignment, and base settings (`mafiaCount`, custom roles, etc.) are all preserved — only the game-session-specific state is wiped. This allows the same group to play multiple rounds without everyone having to re-join.

## Request

<ParamField body="roomCode" type="string" required>
  The 6-digit numeric room code of the room to reset.
</ParamField>

<ParamField body="clientId" type="string" required>
  The browser-generated UUID of the requesting player. Must belong to the room's current host.
</ParamField>

## Response

<ResponseField name="data" type="object">
  <Expandable title="data fields" defaultOpen>
    <ResponseField name="ok" type="boolean">
      Always `true` when the reset completed successfully.
    </ResponseField>
  </Expandable>
</ResponseField>

## What Gets Reset

The following fields are cleared or reverted by this endpoint. Settings (`mafiaCount`, `doctor`, `detective`, `lady`, `casualMode`, `customRoles`) and the player roster are **not** affected.

<ResponseField name="Room status" type="string">
  Set from `started` or `finished` back to `waiting`.
</ResponseField>

<ResponseField name="Room roundState" type="null">
  Cleared to `null` — all round progress, actions, votes, and events are discarded.
</ResponseField>

<ResponseField name="Player role" type="null">
  Each player's assigned role is set to `null`.
</ResponseField>

<ResponseField name="Player has_confirmed" type="boolean">
  Reset to `false` for all players.
</ResponseField>

<ResponseField name="Player is_narrator" type="boolean">
  Reset to `false` for all players.
</ResponseField>

## Error Responses

<ResponseField name="400 — Missing roomCode or clientId" type="string">
  One or more required body fields are absent or empty.
</ResponseField>

<ResponseField name="403 — Player not found" type="string">
  No player with the given `clientId` exists in this room.
</ResponseField>

<ResponseField name="403 — Only host can reset the game" type="string">
  The calling player exists but does not hold the host flag.
</ResponseField>

<ResponseField name="404 — Room not found" type="string">
  No room matches the provided `roomCode`.
</ResponseField>

<ResponseField name="405 — Method not allowed" type="string">
  Request was not `POST`.
</ResponseField>

<ResponseField name="500 — Failed to reset players" type="string">
  Supabase error while clearing player role data.
</ResponseField>

<ResponseField name="500 — Failed to reset room" type="string">
  Supabase error while updating the room status and settings.
</ResponseField>

## Example

```javascript
const response = await fetch('/api/rooms/reset', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    roomCode: '123456',
    clientId: 'a1b2c3d4-e5f6-7890-abcd-ef1234567890'
  })
});
const { data } = await response.json();
// data.ok === true — room is back in 'waiting' state
console.log(data.ok);
```

<Tip>
  After a successful reset, every player's polling loop will observe `status: "waiting"` and `role: undefined` in the next `/api/rooms/state` response. The frontend should navigate players back to the lobby screen when it detects this transition.
</Tip>

<Note>
  Only the host can reset the room. If the host has left the room, the next player in the join order is automatically promoted to host via the `/api/rooms/leave` logic.
</Note>
